# Сборка и проверка

## Требования

* Windows x64; готовый патч и его компоненты имеют архитектуру x86.
* Python 3.10+ со стандартной библиотекой.
* .NET Framework 4.8 (входит в поддерживаемые Windows 10/11).
* Интернет для первой загрузки закреплённых инструментов.

`tools/dependencies.lock.json` фиксирует Zig 0.15.2, Roslyn 4.14.0 и официальный
DDrawCompat 0.7.2 вместе с URL и SHA-256 архивов. Компиляторы и DDrawCompat
не хранятся в Git. Загрузки сохраняются в игнорируемой `.tools/`.

## Одна команда

```powershell
python tools/build.py
```

Результат: `build/dist/Brother-Compatibility-Patch-1.0.zip`, установщик,
`SHA256SUMS.txt` и `build/build-info.json` с хешами входов и результатов.
Путь к рабочей папке и личные настройки в этот отчёт не записываются.
Сборка ничего не устанавливает и не запускает игру.

Параметры:

```powershell
python tools/build.py --output build/custom --tools-dir .tools
python tools/build.py --game "D:\Games\Brother-original"
python tools/build.py --test-components
```

`--game` проверяет оригинальные DLL, выполняет всю цепочку Python-генераторов
из `patches/generators/` и требует точного совпадения результата с эталонными
хешами и бинарными изменениями. Входная игра используется только для чтения.
Исправленные DLL записываются в `build/engine/`, которое не публикуется.

`--test-components` дополнительно создаёт `rea_audio_test.dll`. Она содержит
управление искусственными сбоями и никогда не включается в установщик.

## Как устроен пакет

Обычная сборка использует проверяемые `patches/engine/*.b2patch`, компилирует
наши компоненты и формирует новый манифест с их фактическими хешами.
Таким образом правка исходников установщика или звукового компонента не
требует копии оригинальной игры. Для изменения машинного кода самого движка
нужен поддерживаемый оригинал и проверка генераторов.

Пять игровых DLL представлены бинарными изменениями. В пакете нет их целых
оригинальных или исправленных копий. DDrawCompat скачивается отдельно,
проверяется и включается без изменения.

Установщик принимает только оригинальные хеши, текущую версию и явно
перечисленные предыдущие версии. Для наших компонентов предусмотрены
`KnownVersions`, для игровых DLL — проверенные переходы `Updates`.
Неизвестные изменённые файлы не перезаписываются.

## Повторяемость

Roslyn запускается с `/deterministic`, без PDB и с нормализацией путей.
У собственных нативных DLL нормализуются метки PE; DDrawCompat не меняется.
ZIP имеет постоянные даты,
порядок файлов, атрибуты и формат ZIP_STORED, исключающий различия zlib.

```powershell
python tools/reproducibility.py --tools-dir .tools
```

Проверка собирает проект из двух отдельных копий исходников и сравнивает
байты установщика, пакета, собственных компонентов и ZIP.
Это проверка повторяемости в одном закреплённом окружении. Различающиеся
версии Windows/.NET reference assemblies требуют отдельного сравнения;
совпадение на всех возможных системах не заявляется.

Ранее собранные до публикации EXE использовали старый компилятор с меняющимися
метками и MVID. Их хеши могут отличаться от сборки этого проекта. Хеши
опубликованного релиза находятся рядом с его файлами в Releases.
